# DarkPortrait's .dotfiles
Lives in the `~/.dotfiles` directory. Contains config files for vim, tmux, bashrc, zsh, git and opencode.

## Dotfiles

### VIM Config
The .vimrc is moved to .vim and symlinked to the original location.
```bash
ln -s ~/.dotfiles/.vimrc ~/.vimrc
```

### GIT Config
The .gitconfig is also in the .vim directory for convenience.
```bash
ln -s ~/.dotfiles/.gitconfig ~/.gitconfig 
```

It holds no identity. Name and email come from `GIT_AUTHOR_*`/`GIT_COMMITTER_*`
in `secrets.zsh`, and the signing key from `GIT_CONFIG_KEY_0=user.signingkey`
there. Name that key explicitly instead of relying on email matching: gpg will
not resolve the `Name <email>` string git hands it as the signer, and commits
fail with `skipped "...": No secret key`. Apps not started from a shell (e.g. a
GUI git client) won't see these variables.

### TMUX Themes
Clone the theme repository to `~/.tmux-themepack`
```bash
git clone https://github.com/jimeh/tmux-themepack ~/.tmux-themepack
```

Update the `~/.tmux.conf` to link to the theme I want
```bash
source-file ~/.tmux-themepack/powerline/default/green.tmuxtheme
```

Symlink with the config file for tmux 
```bash
ln -s ~/.vim/.tmux.conf ~/.tmux.conf
```
### Copy colors and templates to .vim

```bash
mkdir ~/.vim/colors/
mkdir ~/.vim/templates/
ln -s ~/.dotfiles/colors ~/.vim/colors
cp -r ~/.dotfiles/templates/ ~/.vim/templates/
```

### LSP Setup for Vim

The `.vimrc` is configured to use Python LSP (Language Server Protocol) for features like diagnostics, auto-completion, and code navigation.

1. Create a virtual environment in the dotfiles directory:
```bash
cd ~/.dotfiles
python3 -m venv env
```

2. Install python-lsp-server with all optional dependencies:
```bash
source env/bin/activate
pip install 'python-lsp-server[all]'
```

The LSP server will now be available at `~/.dotfiles/env/bin/pylsp` and Vim will automatically use it when editing Python files.

**Note**: The `.vimrc` is already configured to use this LSP server path, so no additional configuration is needed.

### FZF Setup for Vim

The Vim configuration includes FZF (fuzzy finder) for fast file and text searching. Install the required dependencies:

```bash
brew install ripgrep fzf
```

These enable FZF commands in Vim like `:Rg` for searching text and `:Files` for finding files.

### BASH Config

Bash on Ubuntu.

```bash
ln -s ~/.dotfiles/.bashrc ~/.bashrc
```

### ZSH Config

`.zshrc` is symlinked, and it sources `functions.zsh` and `secrets.zsh` from this repo.

```bash
ln -s ~/.dotfiles/.zshrc ~/.zshrc
```

Secrets are **not** tracked. Populate them on a new machine:

```bash
cp ~/.dotfiles/secrets-dist.zsh ~/.dotfiles/secrets.zsh
chmod 600 ~/.dotfiles/secrets.zsh
# then fill in the values in secrets.zsh
```

`secrets.zsh` is sourced before oh-my-zsh, so it also holds per-machine
overrides such as `ZSH_THEME`.

### OpenCode Config

The whole `~/.config/opencode` directory lives here and is symlinked in place:

```bash
ln -s ~/.dotfiles/opencode ~/.config/opencode
```

API keys are read from the environment, not the config:
`MULTI_MODEL_GATEWAY_API_KEY` and `DEEPSEEK_CODING_PLAN_API_KEY` (providers) and
`KANEO_API_KEY`/`KANEO_WORKSPACE_ID` (kaneo MCP) come from `secrets.zsh`, so
opencode must be started from a shell that has sourced it.

The background service (TUI and `opencode serve --service`) is a child of the
shell that first launched the TUI, so it only sees env vars that shell had.
Keys added to `secrets.zsh` later are invisible to it until you quit and
relaunch the TUI. Alternatively, store provider keys inside opencode's own
credential store, which every process reads regardless of env:

```bash
opencode auth login     # pick the provider, paste the key
opencode auth list      # see what is stored
```

ClickUp and Figma use their official remote MCPs and log in with OAuth once per
machine:

```bash
opencode mcp auth clickup
opencode mcp auth figma
```

#### Slack MCP (optional)

`slack` is configured but disabled: Slack supports no dynamic client
registration, so the official server needs an OAuth client from your own Slack
app. To enable it:

1. Create an internal app at <https://api.slack.com/apps> (workspace admin
   approval required). Add the redirect URL and user scopes from the `slack`
   entry in `opencode/opencode.jsonc`.
2. Put its Client ID and Secret in `SLACK_MCP_CLIENT_ID`/`SLACK_MCP_CLIENT_SECRET`
   in `secrets.zsh`.
3. Drop `"disabled": true` and sign in from `/mcps`.

Slack only accepts HTTPS redirect URLs outside localhost, so a loopback
`redirect_uri` may need an HTTPS tunnel.

`service.json` (generated by opencode) and `node_modules`/`package*.json` are
gitignored.

## Moving to a New Machine

Clone once, then link the config files into place:

```bash
git clone git@github.com:DarkPortrait/.dotfiles.git ~/.dotfiles

ln -s ~/.dotfiles/.zshrc ~/.zshrc
ln -s ~/.dotfiles/.gitconfig ~/.gitconfig
ln -s ~/.dotfiles/.bashrc ~/.bashrc
mkdir -p ~/.config && ln -s ~/.dotfiles/opencode ~/.config/opencode
```

Vim needs a few extra steps (plugin manager, colors, templates, LSP) — see
[VIM Config](#vim-config) and the LSP/FZF sections below.

Three things are deliberately **not** in git and must be copied or re-created by hand:

1. `~/.dotfiles/secrets.zsh` — git identity, provider API keys, the Kaneo key and
   workspace ID, per-machine overrides. See [ZSH Config](#zsh-config).
2. OpenCode MCP logins — `opencode mcp auth clickup` and `opencode mcp auth figma`.
   See [OpenCode Config](#opencode-config). The Slack MCP is opt-in: fill in
   `SLACK_MCP_CLIENT_ID`/`SLACK_MCP_CLIENT_SECRET` and re-enable it there.
3. OpenCode provider logins — run `opencode auth login` per provider (stored in
   `~/.local/share/opencode/auth.json`, also outside git).

Carry `secrets.zsh` over AirDrop, a password manager or `scp` — not chat or email.

Start opencode from a new terminal so the background service inherits the
variables from `secrets.zsh`. Machine-local state regenerates on its own and
should not be copied: `service.json`, `node_modules`, and everything under
`~/.local/share/opencode` (DB, logs, snapshots).
